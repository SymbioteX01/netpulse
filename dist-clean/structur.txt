===============================================================
 NETFAULT ANALYZER - Network Fault Diagnosis & Root Cause Analyzer
 Data Communication Project (3 Credits / 30 Marks)
===============================================================

---------------------------------------------------------------
 1) PROJECT IDEA (in one line)
---------------------------------------------------------------
This app performs a REAL scan of your machine's network (signal strength,
ping, traceroute, DNS, DHCP), analyzes the data, and reports the fault
with its ROOT CAUSE (including the OSI layer), plus a simulation mode
as a backup for college demos.

---------------------------------------------------------------
 2) TECH STACK
---------------------------------------------------------------
- Node.js backend (server.js) -> runs real Windows commands and returns data
- HTTP/JSON API (pure Node core modules - no external dependencies)
- HTML/CSS/JS frontend (index.html) -> GUI + Canvas visualization
- No npm packages, no installation - just run `node server.js`

 4) REAL DIAGNOSTICS (commands run by server.js)
---------------------------------------------------------------
1. netsh wlan show interfaces        -> REAL signal %, SSID, channel, auth, rates
2. netsh wlan show networks mode=bssid -> REAL neighbor network signal scan
3. netsh interface show interface    -> REAL link status (up/down)
4. ipconfig /all                     -> REAL IP, gateway, subnet, DHCP, MAC
5. ping <gateway>                    -> REAL gateway RTT, packet loss
6. ping 8.8.8.8                      -> REAL internet RTT, loss (internet check)
7. ping 1.1.1.1                      -> cross-check (second path)
8. nslookup google.com               -> REAL DNS resolution time + server
9. nslookup 8.8.8.8 / 1.1.1.1        -> extra DNS latency tests (multi-DNS check)
10. tracert -d -h 15 8.8.8.8          -> REAL hop-by-hop path + per-hop latency
11. arp -a                            -> REAL ARP table (gateway MAC)
12. route print 0.0.0.0              -> default gateway (fallback)
13. ping -f -l 1472 <gateway>        -> MTU discovery (payload 1472 = MTU 1500)
14. ping -6 ::1 + internet IPv6 test -> IPv6 stack check
15. ipconfig /release + /renew       -> Fix Action: DHCP renew (button in UI)
16. ipconfig /flushdns               -> Fix Action: DNS cache flush (button in UI)

EXTRA DATA EXTRACTED:
- Gateway MAC vendor (OUI lookup from ARP table) -> shown next to gateway
- Scan history: every scan auto-saved to data/history.json (last 25), browsable/compareable in UI
- Gateway vendor shown on the Live tab

OUTPUT PARSING: server.js parses each command's raw output into clean
JSON that the browser consumes.

---------------------------------------------------------------
 5) DIAGNOSIS ENGINE (analyzer.js) - The BRAIN of the project
---------------------------------------------------------------
Input: parsed diagnostic JSON
Process: extract signatures, match rules
Output: [ { fault, rootCause, osiLayer, severity, confidence%, fix } ]

RULES (signature -> root cause):
  a) WiFi signal < 50%             -> Weak signal / range issue (L2)
  b) Signal OK + jitter > 60ms     -> WiFi interference / channel congestion (L2)
  c) Gateway ping 100% loss        -> Link down / cable fault (L1)
  d) Internet ping fails + gateway OK -> ISP / router WAN issue (L3)
  e) Ping OK + DNS fails          -> DNS misconfiguration (L7)
  f) DHCP APIPA 169.254.* IP       -> DHCP failure (L3)
  g) Traceroute loss at hop N      -> Fault at that router/link (L3)
  h) 20-40% loss + high RTT       -> Congestion (L3)
  i) Duplex mismatch patterns      -> Duplex fault (L2)
  j) APIPA + no gateway            -> DHCP server unreachable (L3)

Confidence %: every rule has a weight; matching evidence raises the score.
Severity: Critical / High / Medium / Low.
Every root cause also has a fix suggestion.

 7) SIMULATION SCENARIOS (15 total)
---------------------------------------------------------------
LAN MODE (5):
  S1. Healthy LAN                 -> No fault
  S2. Bad Cable / Link Down       -> Physical layer fault
  S3. Network Congestion          -> Congestion, high RTT + loss
  S4. Duplex Mismatch             -> Data Link layer fault
  S5. DHCP Server Down            -> APIPA, no gateway

WIFI MODE (5):
  S6. Healthy WiFi                -> No fault
  S7. Channel Interference        -> High jitter + retransmissions
  S8. Weak Signal / Far Range     -> Signal 30%, intermittent loss
  S9. Authentication Failure      -> Wrong password, no connection
  S10. Too Many Users             -> Delay spikes, airtime congestion

MOBILE MODE (5):
  S11. Healthy Mobile Network     -> No fault
  S12. Weak Coverage              -> RSRP -110 dBm, packet loss
  S13. APN Misconfiguration       -> No data session, no internet
  S14. Carrier Congestion         -> High latency at peak hours
  S15. Tower Outage               -> No service at all
